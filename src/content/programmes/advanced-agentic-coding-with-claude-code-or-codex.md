## Course Overview

<p>Most AI coding courses stop once participants can prompt a tool into building a prototype. This course goes further: participants build a small resident coding and workflow agent in <strong>Claude Code or Codex</strong> that can remember project context, use tools, run on a schedule, keep logs, and pause for human approval when the work gets risky.</p><p>The course is designed for participants who have already seen the baseline ideas behind AI coding: prompt and context engineering, repo instructions such as <code>AGENTS.md</code> or <code>CLAUDE.md</code>, file search, tool choice, skills, MCPs, subagents, code review, testing, documentation, and worktrees. We revisit those ideas through one coherent build instead of treating them as disconnected revision slides.</p><p>We also touch on the emerging shape of agentic engineering: designing loops that find work, hand it to agents, capture state outside the chat, separate maker and checker roles, and bring a human back in when judgement matters.</p><p>The build can be framed around a theme such as Humanitarian Assistance and Disaster Relief (HADR), where an agent researches a developing incident, monitors selected public sources, prepares cited updates, and generates reports. The exact theme may vary, but the pattern stays the same: a real workflow with sources, changing context, outputs, logs, tests, diagrams, and approval gates that a human can inspect.</p>

## Lesson Outcomes

<p>By the end of this course, participants will have built and reviewed a working mini-agent system that can:</p><ul><li data-preset-tag="p"><p><strong>Maintain useful project memory.</strong> Store repo instructions, task notes, decisions, source summaries, and reusable operating procedures without stuffing every prompt with stale context.</p></li><li data-preset-tag="p"><p><strong>Use tools with clear boundaries.</strong> Decide what belongs in a skill, what belongs in an MCP or tool integration, and what should stay as plain repo instructions.</p></li><li data-preset-tag="p"><p><strong>Run a research and monitoring workflow.</strong> Collect source material, track changes, produce situation updates, and generate a final report with citations and human review points, using HADR or another comparable theme as the course context.</p></li><li data-preset-tag="p"><p><strong>Control token and model use.</strong> Route planning, execution, review, and documentation tasks to suitable models; reset context deliberately; and keep skills and instructions lean.</p></li><li data-preset-tag="p"><p><strong>Add production guardrails.</strong> Apply sandboxing, credential handling, prompt-injection checks, approval gates, audit trails, and rollback plans to an agentic workflow.</p></li><li data-preset-tag="p"><p><strong>Document the system for human inspection.</strong> Generate tests, review notes, runbooks, and C4-style system views that make the agent's behaviour easier to check.</p></li></ul>

## Curriculum

<h3>Day 1: Planning and familiarisation</h3><p>Participants get comfortable directing an agent through short builds before planning the main course project: a monitoring agent that reads live sources, assesses new events, and publishes a useful dashboard.</p><ul><li data-preset-tag="p"><p>Set up Claude Code or Codex, the working repository, project instructions, and a GitHub-based review workflow.</p></li><li data-preset-tag="p"><p>Build a small API app and a CRUD app to practise planning, implementation, testing, and review with an agent.</p></li><li data-preset-tag="p"><p>Use repo instructions such as <code>CLAUDE.md</code> or <code>AGENTS.md</code>, plan mode, worktrees, and pull requests to keep agent work bounded and inspectable.</p></li><li data-preset-tag="p"><p>Define the monitoring agent's users, sources, outputs, constraints, and vertical slices in a practical product requirements document.</p></li></ul>

<h3>Day 2: Harnesses, loops, and agents</h3><p>Participants turn the project from a prompt-driven app into a resident agent. They examine the anatomy of an agentic system—standing instructions, loop, tools, file-based memory, heartbeat, and output channel—then build those parts progressively.</p><ul><li data-preset-tag="p"><p>Challenge the product plan, file the first vertical slices as issues, and build an end-to-end slice in a worktree with pull-request review.</p></li><li data-preset-tag="p"><p>Build a compact Python agent harness, progressing from a chat loop and standing instructions to tool calls, an autonomous loop, and dashboard output.</p></li><li data-preset-tag="p"><p>Compare the same task across a hand-built harness, Claude Code or Codex, and another coding harness to separate the role of the model from the surrounding system.</p></li><li data-preset-tag="p"><p>Evaluate when to use skills, MCP integrations, command-line tools, APIs, headless runs, and different models.</p></li></ul>

<h3>Day 3: Make it trustworthy, then ship it</h3><p>The final day adds the controls needed to let the agent work with less supervision. Participants finish the automation, run a bounded task in the background, publish the product, and improve it through structured peer feedback.</p><ul><li data-preset-tag="p"><p>Add deterministic hooks, reviewer subagents, checkpoints, persistent memory, and context and token hygiene.</p></li><li data-preset-tag="p"><p>Turn repeated instructions into reusable skills and add a heartbeat using GitHub Actions, a server, or a local scheduler.</p></li><li data-preset-tag="p"><p>Launch a sandboxed background run with explicit success checks and hard limits on time, permissions, and spend.</p></li><li data-preset-tag="p"><p>Publish the dashboard and its supporting site, collect feedback as prioritised issues, work the backlog, and present the finished system.</p></li></ul>
