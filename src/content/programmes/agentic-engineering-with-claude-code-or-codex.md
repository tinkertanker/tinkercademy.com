## Course Overview

<p dir="auto">AI coding agents can now plan, edit, test, and review software inside a development environment. This two-day workshop teaches you how to direct that work and how to check the result.</p><p dir="auto">It's for experienced software developers. You'll build three projects with <strong>Claude Code or Codex</strong>: a small CRUD app, an agent that operates a simulation, and a team AI app. The builds are the vehicle. The point is the concepts: repo instructions, plan mode, tools and MCP, skills, agent loops, evals, token hygiene, and review gates.</p><p dir="auto">You'll work in teams of 3–4. Each participant builds their own CRUD app and simulation agent; teammates review pull requests and share evaluation work. Each team then builds one AI app together. Setup happens in class. The project headings show the learning sequence; they are not a day-by-day timetable.</p>

## Lesson Outcomes

<p dir="auto">By the end of this course, you will be able to:</p><ul dir="auto"><li data-preset-tag="p"><p><strong>Direct an agent from a product brief.</strong> Write a short PRD, use plan mode, keep standing instructions in <code>CLAUDE.md</code> or <code>AGENTS.md</code>, and check the result against the brief rather than accepting the first build.</p></li><li data-preset-tag="p"><p><strong>Choose the right kind of instruction.</strong> Decide what belongs in a skill, what belongs in an MCP or tool, what belongs in repo instructions, and what should stay as a one-off prompt.</p></li><li data-preset-tag="p"><p><strong>Build an agent loop you can inspect.</strong> Give the agent state, typed tools, and hard limits; keep memory outside the chat; separate model work from deterministic code; stop the loop on purpose.</p></li><li data-preset-tag="p"><p><strong>Evaluate behaviour, cost, and quality.</strong> Write evals, use subagents as independent checkers, compare models on the same evidence, watch token use and prompt caching, and add quality gates before you merge.</p></li><li data-preset-tag="p"><p><strong>Review and ship with a team.</strong> Use worktrees, pull requests, and a second reviewer so agent-written code stays bounded. Apply the same techniques to a small team app that does not need an agent loop.</p></li></ul>

## Curriculum

<h3>Setup</h3><p dir="auto">Form a team and prepare Claude Code or Codex, GitHub, and the course tools. You'll also get the course context: how coding agents moved into the development environment, and which old habits (hand-typing every line, reviewing every diff by eye) this workshop asks you to replace with conventions, constraints, and review.</p>

<h3>Project 1: CRUD app</h3><p dir="auto">Turn a product brief into a small working application. This is the fast first pass: give the agent the complete brief, let it build, then check the result yourself. The concepts here are product thinking, plan mode, and review against a PRD.</p><ul dir="auto"><li data-preset-tag="p"><p>Write a one-page PRD and ask Claude Code or Codex to build from it.</p></li><li data-preset-tag="p"><p>Keep the scope small: authentication, a database that survives restart, create/read/update/delete, and one access rule.</p></li><li data-preset-tag="p"><p>Check the app as two users, compare it with the brief, and fix important failures.</p></li></ul>

<h3>Project 2: Simulation agent</h3><p dir="auto">Play a simulation first so the problem is concrete, then build an agent that operates it. Each participant works in a separate repository; teammates review pull requests and share evaluation work. The aim is to understand the complete system and improve it with evidence, not to add features.</p><ul dir="auto"><li data-preset-tag="p"><p><strong>Tools, MCP, and skills.</strong> Direct the agent through the simulation, then extract a reusable skill from what worked. Learn when a typed tool, an MCP connection, or a skill is the right mechanism.</p></li><li data-preset-tag="p"><p><strong>Loops, state, and memory.</strong> Build a task-neutral tool loop with standing instructions, typed tools, and limits. Keep persistent state outside the chat window.</p></li><li data-preset-tag="p"><p><strong>Evals, cost, and quality gates.</strong> Inspect token use and prompt caching. Write evals with subagents. Compare models on the same evidence. Put automated checks in front of the merge, then make one measured change and re-test.</p></li></ul>

<h3>Project 3: Team AI app</h3><p dir="auto">Apply the course techniques in one team project. The simulation was the worked example; this app does not need that theme, and it does not need an agent loop. Use the simplest design that solves the problem.</p><ul dir="auto"><li data-preset-tag="p"><p>Choose a small idea with a clear user, input, output, and one useful task for the model.</p></li><li data-preset-tag="p"><p>Use at least three techniques from the course: at least one that controls how the app uses the model, and at least one that tests or constrains it.</p></li><li data-preset-tag="p"><p>Build the minimum input-to-output path first, then split remaining work across branches (and worktrees where useful), with review before each merge.</p></li></ul>

<h3>Presentations and conclusion</h3><p dir="auto">Explore Claude Code on the web, present the AI app, and plan what comes next. Each team explains the problem, the input-to-output path, the three techniques they chose, and one item of evidence.</p>
