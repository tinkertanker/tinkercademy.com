## Course Overview

<p dir="auto">AI coding agents can now plan, edit, test, and review software inside a development environment. This two-day workshop teaches you how to direct that work and how to check the result.</p><p dir="auto">It's for experienced software developers. You'll build three projects with <strong>Claude Code or Codex</strong>: a small CRUD app, a HADR (Humanitarian Assistance and Disaster Response) dispatch agent, and a team AI app. You'll also evaluate model behaviour, cost, and quality.</p><p dir="auto">HADR is the worked example: an agent that turns imperfect emergency reports into fire-truck dispatches. You play the game first so the problem is concrete, then build the agent one layer at a time (intake, reconciliation, memory, and a dispatch loop) and improve it with evidence rather than extra features.</p><p dir="auto">You'll work in teams of 3–4. Each participant builds their own CRUD app and HADR agent; teammates review pull requests and share evaluation work. Each team then builds one AI app and presentation together. Setup happens in class. The project headings show the learning sequence; they are not a day-by-day timetable.</p>

## Lesson Outcomes

<p dir="auto">By the end of this course, you will have:</p><ul dir="auto"><li data-preset-tag="p"><p><strong>Directed an agent through a product brief.</strong> Turn a one-page PRD into a small CRUD app, then check it as two users against the brief.</p></li><li data-preset-tag="p"><p><strong>Played, then built, a HADR dispatch agent.</strong> Connect Claude to a simulated disaster, play complete episodes, and extract a reusable skill before you automate the pipeline.</p></li><li data-preset-tag="p"><p><strong>Built the agent one layer at a time.</strong> Plan, implement, and review report and incident stores; add a task-neutral tool loop; then complete intake, reconciliation, dispatch, and replanning.</p></li><li data-preset-tag="p"><p><strong>Evaluated model behaviour, cost, and quality.</strong> Inspect token use and prompt caching, write evals with subagents, compare models on the same evidence, and add quality gates before you merge.</p></li><li data-preset-tag="p"><p><strong>Shipped a team AI app.</strong> Apply at least three course techniques to one shared product with a complete input-to-output path, then present it with evidence.</p></li></ul>

## Curriculum

<h3>Setup</h3><p dir="auto">Form a balanced team and prepare Claude Code or Codex, GitHub, and the course tools on your own machine. You'll also get the course context: how coding agents moved into the development environment, and which old habits (hand-typing every line, reviewing every diff by eye) this workshop asks you to replace with conventions, constraints, and review.</p>

<h3>Project 1: CRUD app</h3><p dir="auto">Turn a product brief into a small working application. This is the fast first pass: give the agent the complete brief, let it build, then check the result yourself.</p><ul dir="auto"><li data-preset-tag="p"><p>Choose a small collaborative tool, write a one-page PRD, and ask Claude Code or Codex to build it.</p></li><li data-preset-tag="p"><p>Keep authentication, a database that survives restart, create/read/update/delete, and one access rule.</p></li><li data-preset-tag="p"><p>Check the app as two users, compare it with the PRD, and fix important failures.</p></li></ul>

<h3>Project 2: HADR agent</h3><p dir="auto">Play the dispatch game, then build and evaluate an agent that turns imperfect reports into fire-truck dispatches. Each participant works in a separate repository; teammates review pull requests and share the evaluation work. The aim is not to add every possible HADR feature. The aim is to understand the complete system and improve it with evidence.</p><ul dir="auto"><li data-preset-tag="p"><p><strong>Understand the task.</strong> Learn the mission and information boundaries, then direct Claude through complete episodes before you inspect or automate the pipeline.</p></li><li data-preset-tag="p"><p><strong>Build the foundations.</strong> Implement report and incident stores from a specification; turn play into a reusable skill; inspect token use and caching; write evals with subagents; build a task-neutral tool loop; then add quality gates and merge a baseline.</p></li><li data-preset-tag="p"><p><strong>Complete and evaluate the pipeline.</strong> Configure dispatch with state, instructions, and typed tools; convert human text into structured reports; match duplicate and conflicting reports in code; make one measured change when new evidence arrives; compare models on the same evidence; then run the assessment game.</p></li></ul>

<h3>Project 3: Team AI app</h3><p dir="auto">Apply the course techniques in one team project. HADR was the worked example; this app does not need the HADR theme, and it does not need an agent loop. Use the simplest design that solves the problem.</p><ul dir="auto"><li data-preset-tag="p"><p>Choose a small idea with a clear user, input, output, and one useful task for the model.</p></li><li data-preset-tag="p"><p>Use at least three techniques from the course: at least one that controls how the app uses the model, and at least one that tests or constrains it.</p></li><li data-preset-tag="p"><p>Build the minimum input-to-output path first, then split remaining work across branches (and worktrees where useful), with review before each merge.</p></li></ul>

<h3>Presentations and conclusion</h3><p dir="auto">Explore Claude Code on the web, present the AI app, and plan what comes next. Each team explains the problem, the input-to-output path, the three techniques they chose, and one item of evidence.</p>
